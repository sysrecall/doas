Diary of a Stranger — App Map

A quiet pool of strangers' latest diary pages. Snapshot of the code at commit HEAD ≈ 268bf5b — it may drift from the repository as the project changes beyond this point.

What the app is, in three pieces

The pool — a Node/Express server with a SQLite file (webapp/): it stores writers' latest entry only (one row per account), serves random anonymous "peeks", and holds sentence-level hearts, ≤140-char comments, reports and a moderation desk. No JavaScript is sent to readers — everything is server-rendered forms.

The plugin — an Obsidian plugin (plugin/) with one command and four settings (pool address, diary folder, username, password). It picks your newest diary note, shows a preview with mood-chip toggles, and sends it a wall POST to the pool. Optional auto-publish (on start, and on/after saves).

The contract — the point the two meet: POST /api/publish. Its exact behavior is machine-checked by npm test against a throwaway pool, so the plugin and the server can drift safely apart.

To change something, start here

  • Comment length (140) → webapp/routes/reactions.js, MAX_COMMENT (and the placeholder text in webapp/views/entry.js).
  • Ban list / refusal wording → webapp/lib/banned.js.
  • The seven mood chips → webapp/lib/chips.js — then mirror the list in plugin/main.ts (CHIPS) so the preview pre-checks match.
  • Wordings (masthead, footer, invites) → webapp/views/layout.js and the view files in webapp/views/.
  • Plugin defaults or new settings → plugin/main.ts, DEFAULT_SETTINGS; rebuild with npm run build:plugin.

A practice to reuse

Test the interface the way its consumer actually uses it. In this project the plugin and server are separate programs; a function-level test would have invited silent breakage. devpost/checks/contract-test.mjs instead replays the plugin's exact HTTP requests (success, replacement, wrong password, banned word, preflight CORS, malformed JSON) against a throwaway pool and asserts the pool's observable behavior — so when npm test is green, the plugin and server agree. When the chips refactor later missed importing normalizeTag, this test failed loudly (trace: commits 89b693f → 3f4b4fb) while typechecking stayed green. On any project with moving parts, prefer one such "rehearse the real request" test plus a short live probe over many speculative unit tests.
